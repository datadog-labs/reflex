THE SIMULATION CONTRACT

Pressure has a memory.

Each downstream has a fixed worker pool and a bounded FIFO queue. Latency multipliers change the processing speed of work already in flight. Errors consume worker time too.

Load feeds failure

Stress approaches a target based on active plus queued requests, normalized by worker count. It rises with pressure and decays more slowly after relief. Request failure probability combines injected faults with peak stress experienced while running.

target = clamp((outstanding / workers − 0.75) / 2, 0, 1)
stress(t + Δ) = target + (stress(t) − target) · exp(−Δ / τ)
P(error) = 1 − (1 − peak fault) · (1 − stress error factor · peak stress²)

Stress is integrated analytically between events. It increases failure probability; the queue and prescribed slowdown cause latency. The model has no hidden breaker advantage.

Timeout is not cancellation

A client reports exactly one outcome. Timed-out work keeps waiting or running until the downstream finishes. Late success is not useful client success. Work after timeout is measured separately.

A fair replay

Algorithms receive the same Poisson arrival trace, service-work requirements, and random error draws. A breaker sees client responses and deadlines—not future faults or internal server stress. The threshold policy uses Reflex to enforce Closed → Open → Half-open transitions.

The charts stop at the scenario horizon. Summary metrics cover all requests offered in that window and their eventual outcomes. At the horizon, the prescribed environment returns to normal so outstanding work can drain.

This is a configurable synthetic model, not a calibrated production-service model. Jev integration and multi-seed statistical benchmarking come next.
