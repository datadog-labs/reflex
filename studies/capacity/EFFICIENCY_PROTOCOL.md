# Efficiency-prompt follow-up

This post-hoc follow-up is motivated by the original experiment's tendency to retain near-maximum capacity. The original instruction already mentioned resource cost, but subordinated it to completion within a fixed SLO. The new fixed instruction treats queue delay and capacity efficiency as competing goals, explicitly favors safe drains when demand falls, considers both CPU and memory, and cautions against provisioning for every forecast upper bound. It supplies no numerical utility weights or new utilization target. It is a changed control preference, not a claim to solve a defined optimum or isolate one sentence's causal effect.

The exact instruction is `prompts/efficiency-v1.txt`, frozen before this follow-up's evaluation. There is one prompt version and no outcome-guided iterative prompt search. Reuse all 120 original traces (six patterns, two loads, ten seeds), Jev 1.13.0, the same typed evidence, Reflex machine, guards, actions, tuning for fallback, 10-second decision cadence and one-second equalized delay. Run Jev and Jev + Toto as two new arms. Reuse original cached Toto forecasts: no new forecast RPCs. Retain all original results for paired comparison. These are reused evaluation workloads, not new unseen validation for a hypothesis formed after inspecting the original results. New model responses and collection time can also affect differences.

Report delay directly in seconds. Queueing delay is start minus arrival; end-to-end completion time is queueing delay plus actual execution duration. For each, provide mean, p25, p50 and p99. Main distribution tables pool measured-period completed jobs (request-weighted) and use the higher order statistic, index ceil((n-1)*p), for quantiles. Also report per-trace values and equal-weight trace means; paired uncertainty resamples complete seed blocks, preserving all workload cells. Do not label a mean of per-run quantiles as a pooled quantile. Completed-job delay excludes rejected/unfinished jobs, whose counts and rates must appear beside it. Lower latency coupled with more rejection is not automatically an improvement. The simulator's 60-second queue expiry truncates the completed-job wait distribution; explicitly state this limitation.

Report active node-hours, CPU/memory reservation utilization, applied starts/drains, and rapid direction reversals. Include all inference calls and known token-priced cost, with missing usage visible; retain warm-up costs. Recalculate original-arm delay statistics from their stored job journals without rerunning paid inference. SLO remains recorded for backwards-compatible replay but is not the main outcome in the follow-up report. Do not retune classical baselines: disclose that they were selected using the original SLO objective.

Validate exact workload and forecast identity against the original, identical offered-job cohorts, completed/rejected/unfinished accounting, absence of billing/auth failures, cost arithmetic and deterministic replay of all new decisions. Preserve interrupted attempts if any. HTTP 401/402/403 stops all workers. Do not publish incomplete results as a completed follow-up.
